### What an interface does

An interface connects systems that may store the same information differently.
Here the LIS sends a verified result to an **interface engine**, which transforms
selected fields and routes the message to the EHR. **Middleware** commonly sits
between instruments and the LIS and may manage instrument communication,
quality checks, or result rules. These roles can overlap in a particular
installation; identify which configured transformation actually handles this
message.

**HL7 v2** is a messaging standard. An observation message contains named
segments and numbered fields. The vertical bar separates fields, including
empty fields, and the caret separates components within a field. In the
displayed OBX segment, the observation identifier, value, unit, reference
interval, flag, and status occupy different positions. Moving a value into the
wrong position is a structural error. Keeping it in the right position while
using a code the receiver cannot interpret is a meaning or mapping error.

### Follow the category, not just the number

The sender uses CH and CL for critical high and critical low. The receiver
contract uses HH and LL for those categories, H and L for noncritical
high and low, and N for normal. This is the agreed mapping for this connection.
The exercise preserves the laboratory's already assigned categories; it does
not calculate new critical limits from the displayed reference interval.

CH → H is an attractive but incomplete repair. The receiver recognizes H,
but the critical distinction is lost. CH → HH addresses only one direction;
CL still needs a corresponding mapping. Leave the routine categories unchanged
and route an unexpected category to visible review. Treating an unknown flag as
normal would turn missing knowledge into a clinical assertion.

### What the acknowledgment shows

The receiver returned an application acknowledgment with AA and the matching
message control ID. In this implementation, that means the observation was
accepted and stored; an unknown flag is logged separately. Other implementations
may reject it. Read the receiving system's contract and logs rather than
assuming that every acknowledgment has the same operational meaning.

Transport, message structure, interpretation, and clinical use therefore need
separate evidence. Inspect the official EHR laboratory report, its status,
units, reference information, comments, and flags. If other chart views reuse
these elements, include those views in the agreed validation scope.

### Repair and recovery

The interface analyst implements a versioned mapping in a test environment.
Laboratory and EHR staff verify the resulting report, and laboratory leadership
approves its clinical meaning. Existing critical-result communication procedures
continue during investigation. Correcting a future message does not prove that
an earlier report was corrected, nor does a red indicator prove that the
required communication occurred.

### Which HL7 standard is this?

Health Level Seven (HL7) version 2 messages carry laboratory orders and results. OML^O21 and the older ORM^O01 carry orders; ORU^R01 carries results; ADT messages carry registration changes; ACK messages acknowledge handling. Many US laboratory and public-health guides use version 2.5.1. Local fields and codes still require a written interface agreement and testing.

HL7 version 3 Clinical Document Architecture (CDA) describes clinical documents. Fast Healthcare Interoperability Resources (FHIR) exposes resources such as Observation and DiagnosticReport through web interfaces. It also needs profiles, terminology bindings and testing. Parsing the message structure is syntactic interoperability; preserving the clinical meaning is semantic interoperability.

### Interfaces in the laboratory

| Interface | What it carries |
| --- | --- |
| Registration (ADT) | Patient identifiers and location updates |
| EHR orders and results | Requested examinations and complete reports |
| Billing | Charges associated with completed services |
| Reference laboratory | Referred orders, identifiers and returned reports |
| Instruments and middleware | Test requests, results and instrument flags |

A unidirectional instrument connection only sends results. A bidirectional connection also receives orders by host query (the analyzer asks after scanning a barcode) or download (the LIS sends a worklist in advance). Instrument protocols may use ASTM/CLSI LIS2-A2 or HL7. The interface agreement must state identifiers, status handling, local codes, retries and expected clinical reports.
