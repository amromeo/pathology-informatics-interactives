# Faculty guide: Tracing a Missing Critical Flag

## At a glance

Allow 30 minutes. Use individually or in a small group. Project the case records and the exercise controls; keep the answer key out of view until learners commit to a decision.

Learning objectives: distinguish message receipt from faithful result meaning; compare the source message with the received report; justify the first local check. PIER: 5.2, 5.3, 5.4, 8.1.

## Run of show

| Minutes | Activity | Ask the group |
| --- | --- | --- |
| 0–6 | Read the case and records | What decision has the laboratory been asked to make? |
| 6–21 | Make, test and revise a choice | Which record supports your decision? What could fail? |
| 21–30 | Debrief and retrieval questions | How would you verify this in your own laboratory? |

## Expected answers


Allow 30 minutes. Ask the resident first to locate the last record with the
correct meaning. The LIS has CH; the outbound message still has CH; the EHR
import log identifies a display-table mismatch. Neither the number nor the
network connection needs to be changed.

Have the learner explain OBX-3, 5, 6, 7, 8, and 11 in context. A strong answer
distinguishes the observation code from its interpretation code, final status
from normality, and reference intervals from critical limits. Ask what would
change if the receiver rejected unknown flags instead of accepting the result.

The initial replay is 4/6. Repairing only CH gives 5/6; both critical directions
with unknown-code review give 6/6. CH → H remains wrong. Ask the learner to
explain why a passing category replay still requires validation of actual
reports and review of the affected production interval.

Assess four things: locating the faulty transformation, preserving severity,
testing neighboring categories, and assigning recovery responsibilities.
Do not credit a proposal to resend all reports without checking message
identity, correction behavior, and whether the receiver would duplicate them.

PIER alignment: 5.2, 5.3, 5.4, and 8.1. Harrison/API: Session 3 slides 18–20;
Session 4 slides 3–20. These guide the architecture and interoperability
teaching; cases and message excerpts are original.

Sources: [HL7 observation interpretations](https://terminology.hl7.org/4.0.0/CodeSystem-v3-ObservationInterpretation.html)
for category semantics, and the lesson's explicitly stated interface agreement
for its behavior. This excerpt is not a complete implementation guide.

Ask: Follow the mapping between sending and receiving systems and inspect the message structure. Explain how a received message can still produce an incorrect flag in the displayed report. Have residents support their answer with a specific record or result from this lesson before comparing it with the slides.

These slides provide teaching background. ## Common misconceptions

- “Verified clinical display.” Ask: what does the record actually establish? An acknowledgment establishes receipt at a handoff. Field mapping and the displayed report must also preserve clinically important interpretation.
- “Correct flag translation.” Ask: which conclusion would still need evidence? An acknowledgment establishes receipt at a handoff. Field mapping and the displayed report must also preserve clinically important interpretation.
- “Repeat the transmission without inspecting fields.” Ask: what must be checked before making the change? Following the same observation exposes where the flag was lost or translated incorrectly.

## Discussion prompts

1. What supports the case decision? A strong answer includes a specific record and the distinction: distinguish message receipt from faithful result meaning.
2. What would you check locally? A strong answer includes: compare the source message with the received report, because following the same observation exposes where the flag was lost or translated incorrectly.
3. Who needs to participate? A strong answer includes an interface analyst and separates technical work from clinical approval.

## Group variant

Assign laboratory director, LIS analyst, laboratory operations and clinical service roles. Add clinical informatics and a patient advocate when considering ordering or chart use. Ask each person to state one requirement, one risk and the evidence needed before approval. The director then summarizes what can proceed and what must be resolved.

## Assess transfer

Annotate one approved message with identifiers, status and flag fields, then compare its chart display. A strong response names the record, responsible person, first check and an unresolved risk. Use the three learner retrieval questions to distinguish an unsupported shortcut from a reasoned decision.
