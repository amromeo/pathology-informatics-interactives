# Building and Validating a Laboratory Test

You are the pathology resident helping to set up a new microbiology test. The laboratory is bringing influenza A, influenza B and respiratory syncytial virus (RSV) testing in-house. The emergency department needs each virus shown separately in the electronic health record (EHR).

To start the build in the test system, the laboratory information system (LIS) analyst copied an existing respiratory test. A sample message reached the EHR without trouble, but the report says “Respiratory panel: Detected copies/mL.” The procedure describes a test that only says detected or not detected, and the report does not say which virus was found.

The microbiology director asks you to compare the request, the procedure and the report as it appears, then help work out the fix. The copied settings also decide what happens to failed runs, pending results, specimens, corrections and messages that are sent again. Fixing the first report alone will not show that the new test is ready.

## Terms used in this case

- **Test definition:** the settings that decide how a test is ordered, processed, reported and kept up to date.
- **Result component:** each separately named result an order produces. This panel has three: influenza A, influenza B and RSV.
- **Test system and live system:** the test system is where a build is checked; the live system is used for patient care.
- **Repeat send and correction:** a repeat send is the same result sent again; a correction replaces an earlier result and keeps it in the history.

## Your task

Look at the three source records, set up how results behave, and run the eight report checks. Then write a recommendation for go-live that keeps technical testing separate from clinical and operational approval.

## What you will be able to do

- Compare a clinical request, a procedure and a built report, and find where a copied build went wrong.
- Set up how a test reports positive, negative, pending, failed and corrected results.
- Test a build with normal cases and exceptions before go-live.
- Say who approves a new test and what has to be ready on the day it goes live.
