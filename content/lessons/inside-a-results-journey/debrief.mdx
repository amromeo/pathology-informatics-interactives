## Debrief: separate a verified result from successful report delivery

### What happened in this case


**A result can be final in the LIS and still be unavailable to the clinical team.** The investigation must follow the result through the entire reporting path.

In this case, the analyzer completed the CBC and the LIS released it. The result then waited in the interface queue because a hospital firewall rule blocked the connection to the vendor-hosted EHR. This was a failure in the result-reporting pathway, not a problem with the analytical performance of the analyzer.

### Who was involved

The **LIS team** usually begins by determining whether the result left the LIS and where transmission stopped. **hospital IT** manages the network and firewall. The **EHR vendor or EHR team** helps confirm whether the receiving system accepted the message.

The laboratory remains responsible for making sure its reports reach the correct patient charts. After the connection was restored, the laboratory did not check only this CBC. Staff also checked the queued reports, a new CBC, a report from another laboratory section using the same connection, and the record of results communicated during downtime.

### Local and hosted systems

Local and vendor-hosted systems fail in different places. The laboratory should know who runs each part, how failures are detected, and how results will be reported during an outage.

You cannot tell whether a system is more reliable just because it is local or vendor-hosted. You have to look at how it is connected, monitored, backed up, and supported.

### PIER R5 connection

This case addresses PIER objective **1.4** by asking you to identify common computer and network components and use them to explain a real laboratory reporting problem.

### Who does what

Work with an LIS analyst and a bench technologist. The person making a technical change should document the test evidence; the responsible clinical or operational lead approves the intended use.

### Connection to PIER 1.4

The case asks you to separate a verified result from successful report delivery using laboratory records and explain the consequence of your choice.


### Where the software runs



| Term | Practical meaning |
| --- | --- |
| On-premises | The system runs in the hospital or in a data center operated by the health system. |
| Vendor-hosted | The system runs in an environment operated by the vendor. This may or may not be a cloud service. |
| Cloud | Computing resources are provided through shared, scalable infrastructure rather than a single server assigned only to that institution. |
| Software as a service (SaaS) | The vendor operates and updates the application, which is generally purchased by subscription. The health system still configures, validates, and uses it. |
| Hybrid | Some parts run in the health system and other parts run in an outside environment. |

These labels do not tell you whether a system is reliable. To answer that question, you need to know how it is connected, monitored, backed up, and supported.
