## Debrief: What kept the CBC out of the chart?

The analyzer finished at 09:40. The LIS contained a CBC verified at 09:42, including a hemoglobin of 7.4 g/dL. Those records established that the laboratory had a result to communicate to the ED. Repeating the CBC would not repair the electronic reporting problem.

The LIS analyst then followed the same report to the interface engine. Its queue contained 214 waiting results. Processor use was 18%, memory use was 46%, and the operating system and application were running. The delivery log showed a TCP connection reset. A running application and a connected network adapter therefore did not establish successful delivery.

The firewall log supplied the next piece: the connection from the interface server to the EHR service was being denied. Firewall rules had changed at 09:35. Hospital IT needed to correct the rule for that approved connection. Restarting the interface application would leave the block in place.

## What counted as restoration?

The original CBC needed to appear once in the correct chart. The team also needed to check the other queued reports, a newly released CBC and a report from another section using the same connection. Finally, staff compared the records of results communicated during downtime with the reports now available electronically.

Entering one CBC manually could make that report visible while the queue continued to grow. That is why the exercise gives this action only one passing check. Restoring the connection addresses both the original report and the other reports that depend on it.

The LIS analyst follows the messages and checks the queue. Hospital IT repairs the network rule. The EHR team helps inspect received messages and chart display. The laboratory confirms that its complete reports reached the correct charts and accounts for downtime communications. Local department names may differ; the work still needs named people.

## What does vendor-hosted mean here?

The vendor operates this EHR's computing environment. The hospital still depends on its own network connection to that service. A failure on either side can interrupt reporting.

An **on-premises** system runs in the institution's own computing environment. A **cloud** service supplies computing resources from shared infrastructure that can be allocated as needed. **Software as a service (SaaS)** means the vendor operates the application as a service. A **hybrid** arrangement combines institutional and outside systems. Vendor-hosted does not automatically mean cloud, and none of these labels proves reliability.

For your own laboratory, ask who checks each connection, who can repair it and how results are communicated during an interruption. PIER 1.4 uses these hardware, software and networking distinctions to help you investigate a laboratory problem.
