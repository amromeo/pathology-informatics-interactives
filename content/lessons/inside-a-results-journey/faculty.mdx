# Faculty guide: The Missing CBC

Allow 22 minutes. The learner should finish able to distinguish a released LIS report from successful chart delivery and use system records to locate a failed connection. This addresses PIER 1.4.

## Run of show

Spend 4 minutes on the ED call and LIS check, 8 minutes on the map and component explanation, 6 minutes following the system records and 4 minutes discussing restoration.

## Lead the discussion through the records

Begin with the ED screen. Ask what Pending tells the clinician and what remains unknown. The first useful laboratory check is the LIS: it contains a final CBC verified at 09:42. The technologist can communicate the hemoglobin under the downtime procedure while the analyst investigates.

Give learners time to read the system explanation before building the map. The order is analyzer, LIS, interface engine, firewall/network, EHR. The map highlights the final network connection; it does not imply that the earlier systems communicate without networks.

For component classification, the server and switch are hardware, the operating system is system software, and the LIS and interface engine are applications. TCP/IP supplies communication rules.

Ask learners to explain each record before moving to the next tab:

- **Analyzer:** testing finished at 09:40 and the LIS accepted the result. This does not establish EHR display.
- **LIS:** verification at 09:42 rules out a result still awaiting laboratory release. It does not establish the next transfer.
- **Interface:** 18% processor use and 46% memory use argue against overload at the recorded time. The running application, queue of 214 results and connection-reset log direct attention to delivery.
- **Firewall:** the deny record identifies the blocked connection to the EHR service. It cannot establish whether a hemoglobin measurement is analytically correct.

## Explain the repair and checks

Hospital IT restores the rule for the approved connection. The LIS analyst then checks delivery. Restarting the application leaves the firewall block intact; repeating the CBC produces another result waiting on the same connection.

Run the checks after selecting manual entry as well as after selecting the firewall repair. Manual entry passes the original-CBC check only. Ask why that is insufficient for the other queued reports, new CBC, other laboratory section and downtime record. The restoration exercise represents the expected consequences of the selected action; it is not a live connection test.

The laboratory must confirm the complete report in the correct chart. An acknowledgment alone cannot establish that the clinician sees the intended display. Support teams may be organized differently locally; avoid treating the example department names as universal boundaries.

## Questions to carry into practice

Ask the learner to name the next record to inspect when a result is final in the LIS but pending in the EHR. A strong answer follows that same result through the interface and receiving system, rather than relying on server uptime.

Ask who would review a corrected result display. The analyst makes and tests the change; the laboratory director or designated laboratory approver accepts the complete report for clinical use.

Use the practicum to obtain a local result-path diagram, the record available at each handoff and the method for accounting for downtime communications. The debrief remains available before all exercises are complete.

## Teaching sources

[API teaching slides](https://www.pathologyinformatics.org/teaching-slide-sets), Harrison Session 1, slides 5, 11 and 14–15, help distinguish hardware, operating systems, applications and networking. Session 3 supplies the connected laboratory-systems context. Use them after discussing what the records show.

[RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html) describes TCP's transport service. The lesson distinguishes transport from the receiving application's acknowledgment and from chart-display review. Retry behavior and support responsibilities in the case describe this hospital's arrangement.
## Common misconceptions

A running server can still have a blocked connection. An accepted message can still need chart-display review. A manual fix for one CBC does not account for the other waiting reports. Ask which record would address each of these different questions.
