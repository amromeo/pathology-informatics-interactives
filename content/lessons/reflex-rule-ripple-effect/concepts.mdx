### What a reflex order does

**Thyroid-stimulating hormone (TSH)** is commonly used to begin assessment of
thyroid function. **Free thyroxine (FT4)** provides additional information when
interpreted with TSH and the clinical context. The test sequence here is the
laboratory's approved adult TSH-with-reflex protocol, not a rule for every thyroid
presentation or patient group.

A **reflex** protocol uses the result of an initial test to determine whether
another test should be ordered under an approved sequence. A clinician's
TSH-with-reflex order authorizes that sequence. A TSH-only order does not authorize
the same automatic addition. The downstream FT4 order must remain connected to
the patient, accession, and initial result that caused it.

### Reference intervals and order thresholds are separate decisions

A reference interval supports result interpretation. An order threshold determines
whether a further test is added. The two values may coincide under an approved
protocol, but changing a displayed interval does not automatically approve a new
order threshold. For this assay, the director explicitly approved both changes.
The issue is that the order configuration still uses the old lower threshold.

Read the four records above. TH-01's display uses 0.27–4.20, while revision 8
compares the result with 0.40 and 4.20. Its 0.30 result meets the old lower branch,
so the reflex process adds an FT4 even though the new approved branch would not.
The order record identifies the revision that was actually used.

### Translate the approved protocol into testable conditions

The sequence applies to adults aged **18 or older** with a **TSH-with-reflex**
order. It requires a **final numeric TSH**. Add FT4 when TSH is **below 0.27 OR
above 4.20 mIU/L**. Values exactly equal to either boundary do not trigger this
protocol. A missing or preliminary result requires review, not substitution of
zero. Pediatric and standalone TSH orders remain outside this rule.

Before creating an FT4, check for a pending or completed FT4 on the **same
accession**. Reuse that order/result instead of creating another. This does not
mean that an old FT4 from an unrelated encounter can always replace a new test.

Start by replaying the unchanged configuration. Then update only the lower
threshold and replay again. Try an inclusive boundary or disable duplicate
prevention to see which actions change. A lower total order count is insufficient:
you must preserve indicated FT4 orders and correctly handle exceptions.
