### Test what each setting does

The cards below put the supervisor's approved destination beside the destination currently stored for each procedure. **Configured** means the setting the program will actually use. **Approved** means the destination the supervisor intended.

First, select **Replay routing cases** without changing a setting. A replay runs the listed procedure codes through the current configuration and compares each destination with the expected destination. It lets the analyst test the settings before applying them to routine work.

Then inspect SP-EX. Change only that entry and replay the cases again. Look at each result, including any failure that remains. Each setting change clears the previous test result because it describes an earlier configuration.

### Decide what happens when a code has no entry

The fifth case uses **SP-NEW**, which has no entry in the dictionary. The setting labeled **Destination when no procedure entry matches** tells the LIS what to do in that situation.

This laboratory requires accessioning staff to clarify an unrecognized procedure and document an appropriate destination. Holding the case for that review keeps the unresolved order visible. Sending it to a work area by default could start the wrong processing before anyone clarifies the examination.
