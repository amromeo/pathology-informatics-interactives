### Test what each setting does

The cards below show, for each procedure, the destination the supervisor approved next to the destination currently stored. **Configured** is the setting the program will actually use. **Approved** is where the supervisor meant the work to go.

First, select **Replay routing cases** without changing anything. A replay runs the listed procedure codes through the current settings and compares where each one goes with where it should go. It lets the analyst test settings before they are used for real work.

Then look at SP-EX. Change only that entry and replay the cases again. Look at every result, including any failure that is left. Each time you change a setting, the last test result is cleared, because it described the old settings.

### Decide what happens when a code has no entry

The fifth case uses **SP-NEW**, which has no entry in the dictionary. The setting labeled **Destination when no procedure entry matches** tells the LIS what to do then.

This laboratory wants accessioning staff to find out what an unrecognized procedure is and record where it should go. Holding the case for that review keeps the unclear order in view. Sending it to a work area by default could start the wrong processing before anyone has checked what the examination is.

### Leave the other services' routes working

The routine biopsy, cytology and frozen-section examples test the routes that were already working. These are the regression checks from the list of terms. Read where each one should go before trying a broad change.

The replay tests how future cases will be routed. The existing accession has already been assigned, and the container itself still needs finding. After testing, use the [recovery decision](#specimen-recovery-title) to plan what accessioning and receiving staff need to do for C-1042-A.
