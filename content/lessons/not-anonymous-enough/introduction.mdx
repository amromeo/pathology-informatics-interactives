# Not Anonymous Enough

## A file prepared after recovery

Two weeks after North River University Hospital's network outage on April 18, 2026, the quality office asks Dr. Maya Chen to help review a file that an investigator wants for research. You are working with Dr. Chen and Priya Nair, the privacy officer. The investigator wants to study how testing was completed and how critical results were phoned during the outage.

Jordan Ellis, the laboratory information system (LIS) analyst, starts from the records put together after the paper work was matched to the restored system. He picks the 18 patient records in this file, all admitted on April 18. He copies birth year, sex, ZIP code, admission date and diagnosis into a worksheet, then replaces names and medical record numbers (MRNs) with study codes. What you see is only the part of the file that describes the patients; it does not yet hold the test-completion and call results the study actually needs.

Each row is one patient in this file. The six specimens in Twelve Hours Offline were a different set of examples. This file is fixed: changing a choice in the downtime lesson does not change its rows.

Jordan keeps a separate lookup file that links each study code to the patient. That lookup file is still sitting in the shared project folder. The column in the export holds the **code**; the lookup file is the **key**. Anyone who can open both can link the row back to a person. Priya has not yet approved who gets the file, which fields it contains or how it will be shared.

## Terms used in this case

- **Export:** information copied out of a system into another file. Here, each row of the worksheet holds selected fields from one patient's record.
- **Direct identifier:** information that names a person outright, such as a name or MRN.
- **Quasi-identifier:** a detail that can help single out a person when combined with other details. Birth year, sex, ZIP, admission date and diagnosis are the five looked at here.
- **Coded data and linkage key:** the file uses codes instead of direct identifiers. A separate key links the codes back to the people.
- **Generalization:** replacing a detailed value with a broader one. For example, 2026-04-18 becomes 2026.
- **Reidentification:** linking a released record back to a person, using a key or other information.
- **Group size, or k:** the number of rows that share the same values in the fields being compared. The k shown is the smallest such group in the file.
- **Protected health information (PHI):** health information that identifies a person and is protected by the Health Insurance Portability and Accountability Act (HIPAA).
- **Safe Harbor and Expert Determination:** the two ways HIPAA allows health information to be deidentified. Safe Harbor lists what must be removed and adds a condition about what the holder knows; Expert Determination needs a qualified expert to assess the risk and write it down.
- **Limited data set and data use agreement:** a limited data set leaves out certain direct identifiers but is still PHI. It can be shared only under a data use agreement that sets out what the recipient may do with it and how it must be protected.

## Your task

Use the filters to see how two facts someone already knows can single out one row. Then change the fields shown and watch the group sizes. Decide what kind of file the original is, and put together a proposal for Priya to review. Explain what each change protects and what the study would lose.

## What you will be able to do

- Follow a patient record into an export, and tell a study code apart from its lookup key.
- Explain why a combination of fields can single out a row after names are removed.
- Work out the smallest group size and explain what it does not tell you.
- Compare deidentifying a file with sharing a limited data set under an agreement.
