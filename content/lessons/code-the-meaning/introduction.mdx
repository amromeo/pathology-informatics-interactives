# Why Laboratory Results Need LOINC

Three hospitals are connecting their laboratory results to a shared clinical record. A clinician wants to see all of a patient's glucose results together, even when they were done at different hospitals. Each laboratory has its own test list, its own local codes and its own display names.

The interface analyst's first draft groups results by display name. **GLU** from Hospital A and **GLUC** from Hospital B end up under different headings, even though both laboratories report serum/plasma glucose in mg/dL. Hospital C, a partner hospital in Canada, also uses **GLU**, but reports in mmol/L. Matching on names would put A together with C and leave B out.

You are the pathology resident reviewing the proposed mapping with the laboratory information system (LIS) analyst and chemistry staff. The messages arrive without trouble; the question is what each result actually is. Look at the test-list extracts below before deciding how the shared record should identify these results.

You will explain why a shared code is needed, look up candidate codes on the Logical Observation Identifiers Names and Codes (LOINC) website, check their definitions against the local test list, and see how a correctly formed standard code can still mislead the system that receives it. You do not need to know any code numbers before you start.

## What you will be able to do

- Map a laboratory result to a code using its full definition.
- Compare the specimen, units, method and timing of two tests.
- Explain why picking the most common code from a search can give the wrong answer.
